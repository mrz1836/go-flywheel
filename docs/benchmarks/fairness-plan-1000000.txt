notes
  - F0 mirrors postgresDriver.Dequeue's inner select verbatim (driver_postgres.go), its scheduled_at bound pinned to a
    fixed instant so the artifact is reproducible. The state list, deleted_at guard, queue IN, and OR-on-class clause
    are byte-identical across all three variants, so the only difference measured is the ordering.
  - The claim names a single queue — the shape the shipped claim reaches jobs_ready in, matching the runtime's own
    claim-plan gate — while rows are seeded across every queue. Its predicate matches 166,667 rows, the ready set.
    F0 walks jobs_ready and stops at LIMIT=8; F1 ranks the whole ready set through a WindowAgg before the LIMIT
    applies, which is the O(ready) cost the ship-or-band decision turns on.
  - Every row is seeded parentless, so COALESCE(parent_job_id, id) makes each job its own partition of one — the
    common case the plan's 1000/1001 paragraph describes. The WindowAgg still processes every ready row, so its cost
    is O(ready) whatever the partition sizes are.
  - F1 carries no FOR UPDATE SKIP LOCKED: PostgreSQL forbids a locking clause on a query with a window function, so a
    shipped fairness claim would rank into a candidate set and re-lock it in a second step. This run measures the
    ranking cost, which is what dominates and what the decision turns on.
  - EXPLAIN (ANALYZE) executes the statement, so every capture ran inside a transaction that was rolled back. The
    seeded table is identical for every variant.

statements

--- F0 ---
SELECT id FROM jobs
    WHERE state IN ('available', 'retryable', 'scheduled')
      AND deleted_at IS NULL
      AND scheduled_at <= '2099-01-01 00:00:00+00'
      AND queue IN ('q0')
      AND (executor_class = 'loadtest' OR executor_class = '')
    ORDER BY priority, scheduled_at
    LIMIT 8
    FOR UPDATE SKIP LOCKED

--- F1 ---
WITH ranked AS (
    SELECT id, priority, scheduled_at,
           row_number() OVER (PARTITION BY COALESCE(parent_job_id, id)
                              ORDER BY priority, scheduled_at) AS rn
    FROM jobs
    WHERE state IN ('available', 'retryable', 'scheduled')
      AND deleted_at IS NULL
      AND scheduled_at <= '2099-01-01 00:00:00+00'
      AND queue IN ('q0')
      AND (executor_class = 'loadtest' OR executor_class = '')
)
SELECT id FROM ranked
ORDER BY priority, rn, scheduled_at
LIMIT 8

--- F2 ---
WITH ranked AS (
    SELECT id, priority, scheduled_at,
           row_number() OVER (PARTITION BY COALESCE(parent_job_id, id)
                              ORDER BY priority, scheduled_at) AS rn
    FROM jobs
    WHERE state IN ('available', 'retryable', 'scheduled')
      AND deleted_at IS NULL
      AND scheduled_at <= '2099-01-01 00:00:00+00'
      AND queue IN ('q0')
      AND (executor_class = 'loadtest' OR executor_class = '')
      AND priority <= (SELECT min(priority) FROM jobs WHERE state IN ('available', 'retryable', 'scheduled')
      AND deleted_at IS NULL
      AND scheduled_at <= '2099-01-01 00:00:00+00'
      AND queue IN ('q0')
      AND (executor_class = 'loadtest' OR executor_class = ''))
)
SELECT id FROM ranked
ORDER BY priority, rn, scheduled_at
LIMIT 8
